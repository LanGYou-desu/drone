# 多传感器协同 · 综合重建 · 智能评估

本文对应大创申报书的研究内容与创新点在软件中的落地方式。设计原则是**一条链路、少量页面**：
数据进入后统一走"时间同步 → 关联融合 → 三维重建 → 预测 → 评估"，不在每个环节单开页面。

```text
可见光/红外/雷达/自选（异构采样率、时钟偏置、遮挡、丢帧）
        │
        ▼
① 时间步同步  timesync.py     时钟偏置估计 + 统一主时间栅格 + 缺测标记
        │
        ▼
② 多传感器协同 fusion.py      一致子集选择 + 关联门限 + 逆方差融合 + 健康度
        │
        ▼
③ 三维重建    reconstruction.py  异常点剔除 + 空洞补全 + 加权平滑 + 逐点置信度
        │
        ├──▶ 总览"综合"轨迹（青色管状体，与重建视觉一致）＋左侧"综合重建"指标面板
        │
        ▼
④ 预测        kinflow/        模型段（≤2 s）+ 运动模型长视界外推（任意步长/点数）
        │
        ▼
⑤ 智能评估    risk.py         六因子可解释评分 + 时间线 + 分级处置建议
```

## 1. 总览：综合轨迹就是"重建结果"

- `POST /api/synthesize` → `data_service.synthesize_trajectory()` 直接调用协同管线；
  传感器不足 2 路或管线异常时才回退到旧的加权平均（`mode='weighted'`）。
- 融合前先做**一致子集选择**：若某传感器与其它传感器的中位距离长期超过关联门限，
  判定其观测的不是同一目标并排除，避免融合轨迹在多个目标之间来回跳。
- 综合轨迹存入 `detection_methods['synthetic']`（含 `pipeline` 质量指标），
  总览以**青色管状体**渲染，并只给综合轨迹标注"重建起点/终点"。
- 左侧面板显示：轨迹帧数、参与传感器数（selected/total）、融合不确定度、
  重建置信度、补洞/剔除帧数，并提供同步频率/关联门限/平滑窗口/最大补洞四个参数
  与"重新重建综合轨迹"按钮（参数随 `POST /api/synthesize` 的 JSON body 传入）。
- 3D 场景用红色圆柱（细环 + 母线 + 半透明侧壁）显示防护区，与轨迹/网格同一视觉语言。
- **参数持久化**：重建参数在重建成功后写回 `config.json`（`synchronization.hz`、
  `sensor_fusion.gate_m`、`reconstruction.smooth_window/max_gap_s`）；评估时防护区与
  预测视界写回 `assessment`。页面刷新、程序重启后都保持上次设置，重建结果与界面一致。
  预测的点数/步长与"实际/仿真"数据源选择则记在浏览器本地（localStorage）。

实测（演示数据，三路同目标）：

| 指标 | 数值 |
|------|------|
| 主栅格 | 10 Hz，239 帧 |
| 参与融合 | 3 / 3 |
| 一致帧占比 | 100% |
| 融合不确定度 | 0.49 m |
| 重建置信度 | 0.91 |
| 管线耗时 | 约 5~130 ms（CPU，含缓存） |

## 2. 时间步同步

- 以采样点最多的传感器为参考，用**三维位置轨迹的归一化互相关**估计时钟偏置
  （位置直接相关比速率相关更抗噪；只用高动态段；粗搜 0.1 s + 精搜 0.02 s；
  相关峰不显著时不做平移并给出低置信度）。
- 统一主时间栅格（默认 10 Hz），重采样并标记空洞/丢帧。
- 质量指标：偏置、相关系数、偏置置信度、覆盖率、最大空档、与多数传感器共识的残差。

## 3. 多传感器协同融合

- 一致子集 → 关联门限聚类（默认 3 m）→ 逆方差加权 `w=1/σ²`；
- 融合不确定度 `σ=1/√Σw`，单传感器时放大 1.5 倍；
- 输出传感器健康度（覆盖率 / 剔除率 / 平均创新量 / normal·degraded·lost）。

## 4. 三维重建

局地中值+MAD 异常点剔除 → Catmull-Rom 补洞（限 `max_gap_s`）→ 三角核+1/σ² 加权平滑
→ 速度/加速度/曲率 → 逐点置信度 `exp(-σ/5)`（补洞点再打 0.6 折）。

## 5. 预测：短视界模型 + 长视界运动模型

- 视界 ≤ 2 s（`k_max × sample_dt = 20 × 0.1`）：KinFlow 在请求时间戳上并行生成，
  支持 0.05~5 s 步长、3~60 个点。
- 视界 > 2 s：前 2 s 用模型，其后按模型段末端的**航向/转率/水平速度/垂直速度**
  做常转率积分（转率按 6 s 指数衰减，保留初始曲率、不持续加速），
  逐点置信度 `exp(-(t-2)/8)` 衰减（最低 0.15）。
- 全段统一经物理投影器约束速度/垂直速率/高度。

多视界实测（同一历史，雷达轨迹）：

| 设置 | 视界 | 位移 | 末端置信度 |
|------|------|------|-----------|
| 5 × 0.2 s | 1 s | 4.0 m | 1.00 |
| 10 × 0.2 s | 2 s | 8.2 m | 1.00 |
| 10 × 0.5 s | 5 s | 17.9 m | 0.69 |
| 20 × 0.5 s | 10 s | 35.0 m | 0.37 |
| 20 × 1.0 s | 20 s | 68.6 m | 0.15 |

## 6. 分析评估：分析与评估合并为一个页面

`/analysis`（导航"分析评估"）同时提供：

- 运动学图表（高度/速度/加速度/曲率），综合轨迹与各平台对比；
- 最佳捕捉时机（预测段内部取候选，跳过锚点与末端外推点，避免"速度为 0"被误判为最优；预测后即可用）；
- 智能评估：防护区参数、风险总分（仪表盘）、六因子拆解、风险时间线、
  分级处置建议、证据质量与传感器状态、未来预测与关键事件。

评估链路：`重建轨迹 → KinFlow 预测（默认 2 s 视界）→ 六因子评分`，
因子权重与阈值见 `config.json → assessment`。

| 因子 | 权重 | 说明 |
|------|------|------|
| 空间接近 | 0.30 | 到防护区边界距离 |
| 接近态势 | 0.25 | 逼近速度与 TTC |
| 高度威胁 | 0.10 | 低空更易抵近 |
| 机动强度 | 0.10 | 速度/加速度/曲率 |
| 预测入侵 | 0.20 | 预测轨迹是否进入防护区 |
| 滞留时长 | 0.05 | 区内停留时间 |

## 7. 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/synthesize` | 重建综合轨迹（总览） |
| POST | `/api/predict` | 单平台/综合轨迹预测，返回 `confidence` |
| POST | `/api/predict_all` | 全平台预测并对齐时间 |
| POST | `/api/sensors/reconstruct` | 同步→融合→重建（供评估/调试） |
| POST | `/api/sensors/assess` | 重建→预测→评估 |
| GET | `/api/sensors/status` | 传感器概览 |

## 9. 已知限制

- 时钟偏置的可观测性依赖目标机动；长直匀速段会给出低置信度并放弃平移。
- 长视界（>2 s）是运动模型外推，仅保证运动学一致与趋势合理，不保证精度。
- 融合假设单一目标；多目标时只保留一致子集，其余传感器判为"已排除"。
- 防护区为圆柱近似。
